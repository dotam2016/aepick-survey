## 1. 공통 규칙

### 1.1 화면 공통

| 항목 | 규칙 |
|---|---|
| 기준 해상도 | 1200 × 1920 (세로형), 뷰포트 스케일링으로 타 해상도 대응 |
| 터치 타깃 | 최소 64×64px |
| 진행률 표시 | 게임 화면 상단 고정: 젬 6개(`● ● ● ○ ○ ○`) + `{n} of 6 · Your Beauty DNA is blooming` |
| 게임 완료 연출 | 젬 1개 점등(0.8초) → 완료 메시지 토스트(2초) → 브릿지 화면 자동 전환 |
| 뒤로 가기 | 없음 (단방향 흐름) |
| 운영자 제스처 | 화면 좌상단 5회 연속 탭 → 확인 → 세션 강제 초기화 |
| **기기 식별** | PAD마다 서로 다른 ID 필요. 최초 1회 `?device=PAD-03` 으로 열어 저장 |

> **기기 ID가 겹치면 안 된다.** 같은 ID를 쓰는 PAD끼리 페어링 코드를 서로 무효화해
> 고객이 QR을 찍어도 체험이 시작되지 않는다.

### 1.2 타임아웃 정책

| 화면 | 무입력 한도 | 동작 |
|---|---|---|
| S00 Attract | 없음 | 고객이 없는 상태이므로 대상 아님 |
| S01 언어, S05 인트로, S13 결과, S15 QR | 60초 | 50초에 경고 모달(10초 카운트) → 응답 없으면 세션 파기 → S00 |
| S06~S11 게임 | 90초 | 80초에 경고 모달 → 파기 시 S00 |
| (공통) 경고 모달 | — | [계속하기] / **[처음으로 돌아가기]** 2버튼 |
| S08 (게임 내 제한) | 게임 자체 10초 룰 별도 | 10초 종료 시 선택분만으로 채점 |

## 2. 화면별 상세 스펙

### S00. Attract (대기화면 + 페어링)

- **레이아웃**: 워드마크 / 헤드라인 / 오늘의 참여자·인기 DNA 통계 / 3단계 안내 / **하단 페어링 QR 카드**
- **데이터**: `GET /api/stats/today` → 누적 참여자 수, 오늘 최다 DNA 유형
- **페어링 동작**
  1. 진입 시 `POST /api/pairings` 로 **일회용 코드** 발급 → QR 표시
  2. **1.5초 간격 폴링** (`GET /api/pairings/:code`)
  3. 고객이 QR을 찍고 앱 계정을 연결하면 `claimed` → 세션 ID·방문 횟수 수신 → S01
  4. 코드가 만료되면(3분) 자동으로 새로 발급 — PAD가 방치돼도 항상 유효한 QR 유지
  5. 발급 실패 시 5초 후 재시도
- **전환**: 클레임 감지 시 자동 → S01 (버튼 없음)

### S01. 언어 선택

- 3개 대형 카드: Tiếng Việt(기본, 최상단) / English / 한국어
- 앱 계정에 선호 언어가 있으면 그 값이 기본 선택된다
- 선택 즉시 전체 UI 언어 적용 → [NEXT] → `PATCH /api/sessions/:id/language` → S05

> **세션은 이미 페어링에서 만들어져 있다.** 이 화면은 언어만 확정한다.

### S05. Core Value 안내

- 6개 젬이 원형 배치된 인트로 + "여섯 번의 선택으로 당신만의 Beauty DNA를 찾아드려요"
- [시작하기] → S06

### S06~S11. 게임 (→ 3장 참조)

### SB. 브랜드 메시지 (브릿지) — 게임 사이 자동 전환 화면

게임 완료 토스트가 끝난 뒤, 방금 측정한 축이 AEPICK에게 어떤 의미인지 전하는 화면을
**3초간 자동 노출**하고 다음 게임으로 넘어간다. 6개 게임 모두에 적용된다.

```
게임1 → 브릿지(repick) → 게임2 → 브릿지(value) → … → 게임6 → 브릿지(trust) → DNA 분석
```

| 브릿지 | 메시지 요지 |
|---|---|
| repick | 한 번의 선택보다 **다시 찾게 되는 만족** |
| value | 저렴한 제품보다 **제대로 값하는 제품** |
| care | 보여지는 화려함보다 **안심하고 쓸 수 있는 기준** |
| trend | 지금의 인기보다 **곧 사랑받을 아름다움** |
| localFit | 한국에서 인기 있는 제품보다 **베트남의 일상에 맞는 제품** |
| trust | 많이 보인다는 이유보다 **실제로 좋았다는 이야기** |

- 디자인 시안이 **문구까지 포함된 완성 이미지**이므로 전체 화면으로 그대로 표시한다
  (`assets/ui/bridge-<key>.jpg`, 1200px 폭 · 장당 약 220KB)
- **입력 없음** — 무입력 타임아웃 대상에서 제외한다
- ⚠️ 현재 이미지에 **한국어 문구가 박혀 있어 브릿지 화면만 한국어 고정**이다.
  베트남 고객 대상 운영 전 대응이 필요하다 ([디자이너 가이드 5장](06_디자이너_가이드.md))

### S12. DNA 분석

- 6개 젬이 DNA 오브 주위를 회전하는 연출
- 진입 시 `POST /api/sessions/:id/complete` 호출 → 스코어·페르소나·추천 브랜드·결과 QR 수신
- **최소 재생 3.5초**
  (v1은 AI 이미지 생성을 기다리느라 8초였다. 생성이 없어져 연출 비트로만 남겼다)
- 서버 응답 실패 시 로컬 계산 점수로 진행(오프라인 폴백)
- 전환: 자동 → S13

### S13. DNA 결과

- 페르소나 대형 타이포 공개 + 설명 2줄
- 핵심 키워드 3개 칩 / 6축 레이더 차트 / "오늘 참여자 중 {p}%만 가진 DNA예요"
- [다음] → S15

### S15. QR·추천

- QR 코드(`https://…/r/{token}`) + "Scan to keep your Beauty DNA"
- 추천 브랜드·제품 표시
- QR 하단 고지: 보관 48시간 / 결과 페이지에서 즉시 삭제 가능
- [체험 끝내기] 또는 60초 타임아웃 → S16

> **이 QR이 고객을 다시 폰으로 부르는 유일한 수단이다.**
> 고객은 입장 시 페어링한 뒤 폰을 넣어두므로, 종료 시점에 화면을 자동으로 띄울 방법이 없다.

### S16. 종료·초기화

- 마무리 시안 이미지를 전체 화면으로 표시 (`assets/ui/end-final.jpg`)
- 로컬 세션 데이터 완전 삭제 → 8초 후 S00 (새 페어링 QR 발급)
- ⚠️ 브릿지와 마찬가지로 **한국어 문구가 박힌 이미지**다

## 2-B. 모바일 화면 (PAD와 독립)

고객이 종료 QR을 찍은 뒤 자신의 폰에서 진행한다.

### M1. 결과 페이지 `/r/:token`

- 페르소나 · 설명 · 키워드
- **[투표하러 가기]** — 이미 투표했으면 완료 페이지로 안내
- 팝업 쿠폰 코드
- DNA에 맞는 추천 브랜드와 각 브랜드의 제품 (SHOP 링크)
- 48시간 후 만료 고지 + [지금 삭제하기]

### M2. 투표 페이지 `/v/:token`

- 팝업 운영 브랜드 **전체**와 각 제품 목록
- **정확히 3개** 선택 (4개째 선택 시 안내 후 차단)
- 하단 고정 바에 선택 수 표시, 3개를 채워야 [투표하기] 활성화
- 이미 투표한 계정은 진입 시 완료 페이지로 이동
- **서버 검증**: 개수 · 중복 · 카탈로그 실재 여부 · 계정당 1회

> **투표는 체험한 본인 계정에 귀속된다.** 결과 토큰 → 세션 → 방문자 순으로 연결한다.

### M3. 투표 완료 페이지 `/v/:token/done`

- 완료 확인 + 선택한 제품 3개(브랜드명 포함)
- "이 화면을 직원에게 보여주세요"

**직원 전용 영역 (히든)**

| 항목 | 규칙 |
|---|---|
| 위치 | 우측 하단 64×64 투명 영역 |
| 여는 방법 | **1.2초 길게 누르기** (짧은 탭으로는 열리지 않음) |
| 인증 | PIN (`STAFF_PIN`) |
| 표시 | **이 고객이 몇 번째 방문인지** — 첫 방문은 1 |
| 조작 | [사은품 지급 처리] — 1회만, 재시도 시 `already_claimed` |

> 짧은 탭이 아닌 **길게 누르기**로 만든 이유: 완료 화면은 고객이 직원에게 보여주려고
> 들고 있는 화면이라, 스크롤 중 우연히 눌러 재방문 횟수가 노출될 위험이 크다.

> ⚠️ **미결** — 완료 화면 스크린샷으로 사은품을 중복 수령할 여지가 남아 있다.
> 현재는 지급 시각 기록과 중복 지급 차단까지만 구현되어 있다.

### M4. 카탈로그 관리 `/admin/catalog` (운영자)

- 브랜드: 이름 · 이모지 · 3개 언어 소개 · 추천 대상 DNA · 축 친화도 · 노출 on/off · 로고 경로
- 제품: 3개 언어 이름 · 가격 · 구매 링크 · 노출 · 이미지 경로
- 추가 · 수정 · 삭제 (브랜드 삭제 시 소속 제품 함께 삭제)
- 저장 즉시 결과·투표 화면에 반영 (빌드 불필요)

## 3. 6게임 상세 규칙 및 스코어링

> 모든 게임은 **주 축 점수(0~100)** 와 **서브타입(결과 문구용)** 을 산출한다.
> 산식은 `packages/shared`에 순수 함수로 구현하고 단위 테스트를 작성한다.

### CORE 1 — EMPTY BOTTLE CHALLENGE (축: Repick)

**콘텐츠**: 가상 제품 3종. 각 제품은 4단계 정보 카드(첫 사용감 → 7일 후 → 한 달 후 → 빈 용기)로 구성.

| 제품 | 프로필 | 4단계 서사 요약 |
|---|---|---|
| A. Viral Glow Serum | 즉각 만족·화제성, 장기 만족 하락 | 첫인상 최고 → 점차 평범 → 재구매 고민 |
| B. Steady Barrier Cream | 첫인상 평범, 장기 효용 상승 | 무난한 시작 → 갈수록 피부가 편안 → 빈 용기 뿌듯 |
| C. Classic Daily Lotion | 익숙한 스테디셀러, 꾸준함 | 늘 쓰던 안정감 → 변함없는 만족 |

**진행**: 제품 카드 3장 나열 → 탭하면 4단계 정보 넘겨보기 → 최종 1개를 REPICK 존에 드래그.

**스코어링**
```
base:  B = 90 | C = 72 | A = 45
탐색 보너스: 2개 이상 제품의 4단계를 끝까지 열람 시 +8 (상한 100)
Repick = min(100, base + bonus)
```
**서브타입**: B→장기 효용 중시 / C→익숙한 제품 선호 / A + 전체 열람→신제품 탐색 성향 / A + 미열람→즉각적 만족 중시

**완료 메시지**: "당신은 순간적인 화제보다 오래 만족할 수 있는 제품을 선택하네요." (선택별 3종)

### CORE 2 — BEAUTY BUDGET (축: Value)

**진행**: Beauty Coin 10개를 8개 가치 슬롯에 드래그 배분(슬롯당 최대 4개). 잔여 코인 실시간 표시. 10개 모두 배분 시 [완료] 활성화. 배분에 따라 화장대가 채워지는 배경 애니메이션.

**가치 가중치(합리성 계수)**

| 슬롯 | 효과 | 성분 | 합리적 가격 | 용량 | 사은품 | 브랜드 | 패키지 | KOL 추천 |
|---|---|---|---|---|---|---|---|---|
| w | 1.0 | 0.9 | 1.0 | 0.8 | 0.5 | 0.4 | 0.3 | 0.2 |

```
Value = round( Σ(coin_i × w_i) / 10 × 100 )   // 이론 범위 20~100
```
**서브타입**: 실용형(효과+가격+용량 ≥ 6코인) / 프리미엄형(브랜드+패키지+성분 ≥ 5) / 혜택형(사은품+KOL ≥ 4) / 균형형(그 외). 복수 충족 시 코인 합이 큰 쪽.

**전체 참여자 정보**: 완료 후 "오늘 참여자들은 평균적으로 '{최다 슬롯}'에 가장 많은 코인을 투자했어요" (서버 집계, 실패 시 생략)

### CORE 3 — BEAUTY SHIELD (축: Care)

**진행**: 8장 카드 그리드 제시 → 10초 타이머 → 신뢰할 수 있는 신호 3장 탭 → [다음]으로 진행.
3장을 채우면 타이머가 멈추고, 제한 시간이 끝나면 선택분만으로 채점한다(진행은 항상 가능).

> **표시 원칙**: 카드의 신뢰도를 시각적으로 구분하지 않는다(딤드·경고색 금지).
> 위험 신호를 미리 표시하면 정답을 알려주는 셈이라 게임이 성립하지 않는다.

**카드 가중치**

| 카드 | 점수 | 성격 |
|---|---|---|
| 전성분 공개 | 33 | 신뢰 |
| 실제 사용 테스트 | 33 | 신뢰 |
| 사용 주의사항 | 30 | 신뢰 |
| 피부 타입 안내 | 28 | 신뢰 |
| 실제 구매 리뷰 | 25 | 신뢰 |
| 판매량 1위 | 12 | 약한 신호 |
| 유명인 추천 | 8 | 약한 신호 |
| 과도한 효과 표현 | 0 | 위험 |

```
Care = min(100, 선택 3장 점수 합 + 시간 보너스)
시간 보너스: 3장을 7초 이내 완료 시 +4
시간 초과: 선택된 카드만 합산(0~2장)
```
**서브타입**: 최고점 선택 카드 기준 — 성분 중심(전성분/주의사항) / 전문가 정보 중심(사용 테스트/피부 타입) / 사회적 인기 중심(판매량/유명인) / 브랜드 신뢰 중심(리뷰+혼합)

### CORE 4 — NEXT BEAUTY WAVE (축: Trend)

**콘텐츠**: 6장 스타일 카드 — Glass Skin, Soft Matte, Natural Peach, Bold Color, Minimal Skin, Y2K Beauty. 카드별 비주얼 + 한 줄 설명.

**진행**: 한 장씩 등장, 3방향 스와이프 또는 하단 버튼 선택.

| 방향 | 라벨 (ko / en / vi) | 점수 |
|---|---|---|
| ← | 관심 없어요 / Not for me / Không hợp tôi | 2 |
| ↑ | 다음에 해볼래요 / I'll try next / Sẽ thử sau | 16 |
| → | 지금 좋아요 / Love it now / Thích ngay | 12 |

```
Trend = round( Σ점수 / 96 × 100 )   // 범위 12~100
```

> **라벨 원칙**: 방향의 의미가 문안만으로 전달되어야 한다(영문 약어 `NEXT`·`LOVE NOW`는
> "다음 유행 예감"과 "현재 선호"의 구분이 모호해 사용하지 않는다).
> 3방향 라벨은 카드 주변(좌·우·상단)과 하단 버튼에 모두 노출해 매핑을 반복 안내한다.
**서브타입**: 트렌드 선도형(NEXT ≥ 3) / 실험적 스타일형(Bold Color·Y2K 중 1+ LOVE/NEXT) / 안정적 취향형(NOT ME ≥ 3) / 대중 공감형(그 외)

**결과 연출**: "당신은 참여자의 {p}%만 선택한 트렌드를 먼저 발견했어요" — 카드별 오늘 투표 분포 대비(서버 집계).

### CORE 5 — HANOI BEAUTY WEATHER LAB (축: Local Fit)

**진행**: 랜덤 상황 1개 제시 → 5쌍 속성 **VS 대결**에서 각각 한쪽 선택 → [완료] → 적합도 게이지 애니메이션.

> **표시 원칙**: 두 속성이 한 쌍임이 드러나도록 좌우 배치 + 중앙 `VS` 배지 + 쌍 단위 컨테이너로 묶는다.
> (10개 목록에서 고르는 형태로 보이면 대결 구조가 전달되지 않는다)

**속성 5쌍**: ①가벼운 제형/리치한 제형 ②매트/글로우 ③지속력/편안함 ④강한 보습/빠른 흡수 ⑤휴대용/대용량

**상황별 최적 조합 테이블** (○=왼쪽, ●=오른쪽)

| 상황 | ① | ② | ③ | ④ | ⑤ |
|---|---|---|---|---|---|
| 34°C 높은 습도 + 오토바이 30분 + 오후 실내 약속 | 가벼운 | 매트 | 지속력 | 빠른 흡수 | 휴대용 |
| 비 오는 출근길 | 가벼운 | 매트 | 지속력 | 빠른 흡수 | 휴대용 |
| 야외 데이트 | 가벼운 | 글로우 | 지속력 | 빠른 흡수 | 휴대용 |
| 장시간 에어컨 환경 | 리치한 | 글로우 | 편안함 | 강한 보습 | 대용량 |
| 주말 여행 | 가벼운 | 매트 | 지속력 | 빠른 흡수 | 휴대용 |
| 저녁 파티 | 리치한 | 글로우 | 지속력 | 강한 보습 | 휴대용 |

```
일치 개수 → 점수: 5→100 / 4→86 / 3→70 / 2→55 / 1→42 / 0→30
Local Fit = 해당 점수
```
**서브타입**: 일치 ≥ 4 → 날씨 적응형 / '지속력' 계열 선택 우세 → 지속력 중시형 / '편안함·보습' 우세 → 편안함 중시형 / '휴대용' + 가벼운 → 휴대성 중시형

### CORE 6 — REVIEW DETECTIVE (축: Trust)

**콘텐츠**: 리뷰 카드 3장. 각 카드에 **단서 돋보기** 2개(탭하면 확대: 별점 상세, 피부 타입 표기, 좋아요 수, 사용 기간 등).

| 리뷰 | 내용 | 신호 |
|---|---|---|
| A | "완전 최고! 무조건 사세요!" ★5 | 높은 별점, 경험 없음 |
| B | "복합성 피부. 처음엔 끈적였지만 일주일 후 당김 감소" ★4 + 사용 사진 | 구체적 경험 |
| C | "SNS에서 유명해서 구매" ♥2.4k | 인기, 정보 부족 |

```
base: B = 92 | A = 48 | C = 42
단서 보너스: 선택 전 돋보기 2개 이상 확인 시 +8 (상한 100)
Trust = min(100, base + bonus)
```
**서브타입**: B→상세 정보 중심 / B+사진 단서 확인→사진·영상 중심 / A→평점 중심 / C→대중 인기 중심

**결과 연출**: "참여자의 {p}%가 같은 리뷰를 신뢰했어요"

## 5. 브랜드·제품 추천 로직

v1은 코드 상수 두 벌(브랜드용·제품용)이었으나, **운영자가 어드민에서 직접 관리하는 DB 카탈로그** 한 벌로 통합했다.

### 데이터
- `brands` — 브랜드마다 `personaTags`(추천 대상 DNA)와 `axisAffinity`(6축 중 강한 축, 0~1)
- `brand_products` — 브랜드에 속한 제품 (SKU 구분 없음)
- 초기값: **브랜드 10개 · 제품 30개**를 더미로 시드. 브랜드 테이블이 비어 있을 때만 1회 실행
  (운영자가 지운 브랜드가 재기동 때 되살아나지 않도록)

### 추천 산식
```
점수 = (페르소나 태그 일치 ? 10 : 0)
     + axisAffinity[상위1축] × 1.4
     + axisAffinity[상위2축] × 1.0
→ 내림차순 4개 브랜드 선정, 각 브랜드의 대표 제품 1개씩 최대 5개
```

### 결과 고정 원칙
추천 결과는 **체험 시점에 확정되어 `results.product_ids` 에 저장**된다.
그 뒤 운영자가 카탈로그를 고쳐도 **이미 발급된 고객의 결과는 바뀌지 않는다.**

### 투표와의 관계
- **추천**: 개인 DNA에 맞는 브랜드 4개 (고객마다 다름)
- **투표**: 팝업 운영 브랜드 **전체**의 제품 (모든 고객에게 동일)

## 6. 다국어 문안 원칙

- 키오스크의 모든 노출 문구는 i18n 키로 관리 (`vi` 기본, `en`, `ko`) — 키 구조는 [03 문서](03_API_데이터명세.md) 참조
- 3개 언어 키 트리 일치는 **자동 테스트로 강제**한다
- 페르소나명·게임명은 영문 고유명 유지, 설명만 번역
- vi 문안은 기계 번역 상태이며 `_note: "[감수 필요]"` 로 표시 — **현지 감수 필요**

### 아직 다국어가 아닌 것 ⚠️

| 대상 | 현재 상태 | 필요 조치 |
|---|---|---|
| 브릿지 이미지 6장 · 종료 이미지 1장 | 한국어 문구가 이미지에 박혀 있음 | 언어별 이미지 제작 또는 글자 분리 |
| 투표 페이지 · 완료 페이지 | 서버 HTML에 한국어 하드코딩 | i18n 적용 |
| 목업 페어링 페이지 | 한국어 하드코딩 | 실제 앱 연동 시 대체되므로 불필요 |

베트남 고객이 주 대상이므로 **위 두 가지는 현장 운영 전에 반드시 해결해야 한다.**
