## 1. 검증 범위 및 방법

| 계층 | 방법 | 도구 |
|---|---|---|
| 채점·페르소나·i18n 로직 | 단위 테스트 | vitest |
| 페어링 동시성 | 병렬 요청 주입 후 DB 대조 | curl 병렬 실행 + SQLite 직접 조회 |
| API | 시나리오 스모크 테스트 | curl + Node |
| 화면 동작 | 브라우저 자동화 (실제 DOM 조작) | 브라우저 도구 |
| 히든 UI | 포인터 이벤트 직접 발생 | 브라우저 도구 |
| 제거된 기능 | 엔드포인트 404 확인 | curl |

> **v2에서 바뀌지 않은 6게임의 인터랙션은 재구동하지 않았다.**
> 채점 로직·게임 컴포넌트가 v1에서 그대로이고 단위 테스트가 붙어 있어, 게임 이후 구간을 API로 검증했다.

## 3. 검증 중 발견·수정된 결함

| # | 결함 | 원인 | 수정 |
|---|---|---|---|
| **E1** | **v2가 v1의 코드를 사용** — i18n을 고쳐도 화면에 반영되지 않음 | v1에서 `node_modules`를 복사할 때 `@aepick/shared` 심볼릭 링크가 **v1 폴더의 절대경로**를 가리킨 채 따라옴 | v2에서 `npm install` 재실행해 workspace 링크 정상화. 이후 타입 체크·테스트·빌드 전량 재수행 |
| **E2** | 결과 조회가 500 | V2-3에서 제거한 `sessions.nickname` 컬럼을 계속 조회 | 참조 제거 |
| **E3** | **어드민 삭제 버튼 무동작** | 본문 없는 `DELETE` 에 `Content-Type: application/json` 을 붙이면 Fastify가 400으로 차단 | 삭제 요청은 인증 헤더만 전송 |
| **E4** | 익명 세션 생성 경로 잔존 | v1의 `POST /api/sessions` 가 호출자 없이 살아 있어, **QR 없이 체험 기록을 만들어 방문 집계·투표 자격을 우회** 가능 | 라우트 제거 |
| **E5** | 결과 페이지에 사라진 기능 잔재 | AI 이미지 히어로·다운로드 버튼 4종·이제 없는 `reasonKey` 참조 | 제거. 그대로 뒀으면 화면에 깨진 키가 노출됐음 |

### 짚어둘 점

**E1은 검증 방식 때문에 드러났다.** 타입 체크와 테스트는 통과했지만 **브라우저에서 실제 화면을 보니**
문구가 바뀌지 않아 발견했다. 자동 검사만 돌렸으면 v2 전체가 v1 코드로 빌드된 채 넘어갔을 것이다.

**E3도 마찬가지다.** curl로는 삭제가 성공해서 API는 정상으로 보였고, **화면의 버튼을 실제로 눌러**
확인했기에 드러났다.

**E4는 문서 작성 중 API 목록을 훑다가 발견했다.** 아무도 호출하지 않아 동작 검증에서는 걸리지 않는 종류의 결함이다.

## 4. 잔여 리스크 및 알려진 제한

| 항목 | 내용 | 대응 |
|---|---|---|
| **앱 연동 미검증** | 현재 목업. 어떤 문자열이든 계정으로 인정 | 앱 팀 협의 후 어댑터 교체 |
| **평문 id 위·변조** | 목업 상태에서는 타인 id로 방문 횟수 조작 가능 | 서명 토큰 검증 권고 |
| **사은품 중복 수령** | 완료 화면 **스크린샷 재사용 여지 남음** | **운영팀 미결** |
| 직원 PIN 무차별 대입 | 시도 제한 없음 | BE 이관 시 추가 |
| 실기기 미검증 | 안드로이드 PAD 실물에서 미확인 | 현장 리허설 필요 |
| 6게임 v2 재구동 | v1에서 미변경이라 API로만 확인 | 현장 리허설 시 함께 확인 |
| 브릿지·종료 이미지 | **한국어 문구가 이미지에 박혀 있음** | 디자이너 작업 필요 |
| 투표·완료 페이지 문구 | 한국어 하드코딩 (i18n 미적용) | 현장 운영 전 필요 |
| 베트남어 문안 | 기계 번역 상태 | 현지 감수 필요 |
| `node:sqlite` | Node 실험적 API 경고 | PostgreSQL 이관으로 해소 |
| 다중 인스턴스 | 페어링 원자성이 **단일 프로세스 직렬 실행에 의존** | 확장 시 DB 레벨 보장 필요 |

## 6. 결론

v2의 **전 구성요소가 팝업 운영 스펙대로 동작함을 확인**했다.

PAD 10대 전제의 핵심인 **페어링 동시성**(동시 클레임 10건 중 1건만 성공, 기기-세션 불일치 0건)과
**투표 무결성**(계정당 1회, 임의 제품 주입 차단)이 검증되었고, 발견된 결함 5건은 전량 수정했다.

다만 아래 세 가지는 **우리가 완결할 수 없는 사항**으로 남아 있다.

1. **앱 연동** — 앱 팀 협의 필요. 현재 목업은 검증이 없어 그대로 운영에 쓸 수 없다
2. **사은품 중복 수령 방지** — 운영팀 결정 필요
3. **다국어** — 브릿지·종료 이미지와 투표 페이지가 한국어. 베트남 고객 대상 운영 전 필수

기술적으로는 인계 가능한 상태이며, 위 세 가지가 정리되면 현장 배포 단계로 진행할 수 있다.
