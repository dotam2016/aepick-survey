# AEPICK BEAUTY DNA v2 — 시연 가이드

> 버전 2.0 · 2026-08-19
> 구성: **노트북(서버) + 태블릿(PAD) + 휴대폰 2대** · 현장 Wi-Fi 사용

---

## 0. v1과 달라진 점 — 먼저 읽어주세요

### 휴대폰이 **2대** 필요합니다

v2는 **QR을 찍어야 체험이 시작**됩니다. 그래서 시연 중 휴대폰이 두 번 쓰입니다.

| 시점 | 용도 |
|---|---|
| 체험 **시작** | PAD 화면의 QR을 찍어 앱 계정 연결 |
| 체험 **종료** | 결과 QR을 찍어 결과·투표 페이지 확인 |

한 대로도 되지만, 관객에게 보여줄 때는 **시작용·결과용을 나누는 편**이 흐름이 끊기지 않습니다.

### 카메라 권한이 필요 없습니다

얼굴 촬영이 없어졌습니다. **태블릿 카메라 권한 설정이 불필요**합니다.

다만 `START-DEMO.bat`은 여전히 HTTPS로 뜹니다(결과 페이지의 공유 버튼이 보안 컨텍스트를 요구).
따라서 **인증서 경고는 그대로 나옵니다.** 고객 휴대폰에도 경고가 뜨므로,
관객 앞에서 매끄럽게 보여주려면 **8번 터널**을 쓰는 편이 낫습니다(정식 인증서, 경고 없음).

### AI 이미지 설정이 없어졌습니다

v1의 `AI_PROVIDER` / `GEMINI_API_KEY` 설정은 **더 이상 아무 동작도 하지 않습니다.**
실행 스크립트에서 제거했습니다.

### PAD가 여러 대면 기기 ID를 지정해야 합니다

같은 ID를 쓰는 PAD끼리는 페어링 코드를 서로 무효화해 **QR을 찍어도 체험이 시작되지 않습니다.**

```
각 PAD에서 최초 1회만:  http://<주소>:8787/?device=PAD-01
```

이후에는 파라미터 없이 열어도 유지됩니다. **1대만 쓰는 시연이면 신경 쓰지 않아도 됩니다.**

## 1. 가장 쉬운 실행 — 더블클릭

| 파일 | 하는 일 |
|---|---|
| **`START-DEMO.bat`** | Node 확인 → (최초 1회) 패키지 설치 → 빌드 → HTTPS 서버 실행 |
| **`START-TUNNEL.bat`** | 위와 같되 **공개 주소(터널)로 실행** — 8번 참고 |
| **`SEED-DATA.bat`** | 대기화면 통계 채우기(1) / 지우기(2) |

- 창에 표시되는 **`KIOSK (TABLET)` 주소**를 태블릿 브라우저에 입력합니다
- 종료: 그 창에서 `Ctrl + C` 또는 창 닫기
- 창을 닫으면 서버도 꺼지므로 **시연 중에는 창을 그대로 둡니다**

터미널에 익숙하다면 `npm run demo` 와 동일합니다.

## 2. 출발 전 준비 (사무실에서 반드시 1회 리허설)

```bash
npm install          # 최초 1회
npm run demo         # 빌드 + HTTPS 서버 기동
```

기동하면 콘솔에 접속 주소가 표시됩니다.

```
  KIOSK  (this PC)   https://localhost:8787/
  KIOSK  (TABLET)    https://10.100.180.111:8787/     <-- 이 주소를 태블릿에 입력
  ADMIN  dashboard   https://localhost:8787/admin      (key: aepick-admin)
  ADMIN  catalog     https://localhost:8787/admin/catalog
```

### 체크리스트

- [ ] 노트북 브라우저에서 `https://localhost:8787/` → **전체 여정 1회 완주**
- [ ] 태블릿에서 LAN 주소 접속 → 인증서 경고 [고급] → [계속] 1회 수락
- [ ] **휴대폰으로 PAD의 QR을 찍어** 페어링 → PAD가 자동으로 넘어가는지 확인
- [ ] 체험 완료 → **결과 QR 스캔** → 결과 페이지 → **투표 3개** → 완료 화면
- [ ] 완료 화면 **우측 하단을 1.2초 길게 눌러** 직원 확인 → PIN 입력 → 재방문 횟수 표시
- [ ] `/admin/catalog` 에서 브랜드 이름 하나 바꿔보고 결과에 반영되는지 확인
- [ ] `npm run demo:seed` 로 대기화면 통계 채우기
- [ ] **노트북 절전/화면잠금 해제**, 태블릿 자동잠금 해제
- [ ] **Dropbox·OneDrive 동기화 일시정지** (파일 잠금으로 빌드가 실패할 수 있음)

> 직원 PIN 기본값은 `1234` 입니다. `START-DEMO.bat` 안의 `set STAFF_PIN=1234` 에서 바꿉니다.

## 3. 현장 세팅 순서 (10분)

1. 노트북·태블릿·휴대폰을 **같은 Wi-Fi**에 연결
2. 노트북에서 `START-DEMO.bat` 실행 → 콘솔의 **태블릿용 주소** 확인
3. `SEED-DATA.bat` → `1` 입력 (대기화면 통계 채우기)
4. 태블릿 브라우저에서 주소 입력 → 인증서 경고 수락 → **전체화면 모드**
   - Android Chrome: ⋮ → 홈 화면에 추가 → 앱처럼 실행
   - iPad Safari: 공유 → 홈 화면에 추가
5. **대기화면에 QR이 보이면** 준비 완료
6. (PAD 여러 대) 각 기기에서 `?device=PAD-01`, `?device=PAD-02` … 로 한 번씩 열기

> **IP가 바뀌면**(Wi-Fi 재접속 등) 서버를 재시작하고 태블릿 주소를 다시 입력합니다.

## 4. 시연 시나리오 (약 5분)

| 순서 | 화면 | 말할 포인트 |
|---|---|---|
| 1 | 대기화면 | "오늘 참여자 N명, 인기 DNA는 …" — 실시간 집계 |
| 2 | **QR 스캔** | **휴대폰으로 직접 찍어 보이기.** 찍는 즉시 PAD가 넘어가는 것이 임팩트 포인트 |
| 3 | 언어 선택 | 베트남어 기본 · 3개 언어 |
| 4 | 6게임 | 각 30초. **CORE1 드래그**, **CORE3 10초 타이머**가 시연 효과가 큼 |
| 4-1 | 브랜드 메시지 | 게임마다 3초 자동 노출 — "AEPICK이 무엇을 기준으로 고르는가" |
| 5 | 분석 | 3.5초 연출 |
| 6 | DNA 결과 | 페르소나 + 6축 레이더 + "참여자 중 N%" |
| 7 | QR·추천 | 맞춤 브랜드 4개 — **고객을 브랜드 부스로 보내는 장치**임을 설명 |
| 8 | **결과 페이지** | 두 번째 휴대폰으로 QR 스캔 → 로그인 없이 본인 결과가 열림 |
| 9 | **투표** | 브랜드 10개 제품 중 3개 선택 → 제출 |
| 10 | **직원 확인** | 완료 화면 우측 하단 길게 누르기 → PIN → **재방문 횟수** |
| 11 | 어드민 | `/admin/catalog` — 브랜드를 현장에서 직접 관리 |

**빠른 시연(2분)**: 게임은 CORE1·CORE3만 보여주고 나머지는 빠르게 진행 → 결과·투표·직원 확인에 집중

### 재방문 시연하기

같은 계정 ID로 **다시 페어링**하면 방문 횟수가 올라갑니다.
"이 고객은 3번째 방문입니다"를 보여주려면 같은 ID로 3회 반복하면 됩니다.

> 단, **투표는 계정당 1회**입니다. 투표를 다시 시연하려면 **다른 ID**로 페어링하세요.

## 5. 현장 트러블슈팅

| 증상 | 원인 | 조치 |
|---|---|---|
| **QR을 찍어도 PAD가 안 넘어감** | 폰이 다른 네트워크 | 같은 Wi-Fi 확인 → 안 되면 **8번 터널** |
| | QR이 만료됨(3분) | 대기화면의 **새 QR**을 다시 찍기 |
| | 여러 PAD가 같은 기기 ID | 각 PAD에 `?device=PAD-01` 지정 (0번 참고) |
| 폰에서 인증서 경고 | 자체 서명 인증서 | [고급] → [계속]. 관객 앞이라면 **8번 터널** 권장 |
| 태블릿에서 **접속 자체가 안 됨** | 다른 Wi-Fi / 방화벽 | 같은 네트워크 확인 → 방화벽에서 Node 허용 → **8번 터널** |
| 현장 Wi-Fi가 기기 간 통신 차단 | AP 격리(게스트망) | **8번 터널**로 우회 |
| **투표가 안 됨** (`already_voted`) | 그 계정은 이미 투표함 | 다른 계정 ID로 페어링 |
| 직원 확인창이 안 열림 | 짧게 눌렀음 | **1.2초 이상** 길게 누르기 |
| PIN이 안 맞음 | 기본값과 다름 | `START-DEMO.bat` 의 `set STAFF_PIN=` 확인 |
| 브랜드가 안 보임 | 노출이 꺼져 있음 | `/admin/catalog` 에서 [노출] 체크 |
| 화면이 멈춘 것 같음 | 무입력 타임아웃 대기 | 화면 탭 또는 경고창의 [처음으로 돌아가기] |
| 세션 강제 초기화 | — | 화면 **좌상단 5회 연속 탭** → 확인 |

## 6. 시연 후 정리

```bash
npm run demo:reset     # 시드 데이터 삭제
```

- **얼굴 사진은 애초에 수집하지 않습니다** (v2에서 촬영 기능 제거)
- 앱 계정 식별자는 해시로만 저장되며 원문이 남지 않습니다
- 결과 페이지는 48시간 후 자동 삭제됩니다
- 시연 데이터를 통째로 초기화하려면 `server/data/aepick.sqlite` 삭제 후 재기동

> **주의**: DB를 지우면 **브랜드·제품 카탈로그도 함께 지워집니다.**
> 재기동 시 더미 10개 브랜드가 다시 시드되므로, 어드민에서 입력한 실제 브랜드 정보가 사라집니다.

## 7. 시연 노트북으로 옮기는 방법

**권장: Dropbox 동기화보다 폴더 복사(USB 등)**

`node_modules`는 파일이 수만 개라 Dropbox 동기화가 매우 느리고, 동기화 중 파일이 잠겨 빌드가 실패합니다.

1. **복사할 것**: `apps/`, `server/src/`, `packages/`, `tools/`, `docs/`,
   `START-DEMO.bat`, `START-TUNNEL.bat`, `SEED-DATA.bat`,
   `package.json`, `package-lock.json`, `tsconfig.base.json`
2. **빼도 되는 것**: `node_modules/`, `apps/kiosk/dist/`, `server/data/`
3. 시연 노트북에서 **Node.js LTS(22 이상) 설치** → `START-DEMO.bat` 더블클릭
   (최초 실행 시 자동으로 `npm install` — **인터넷 필요, 3~5분**)
4. **한국에서 이 과정을 끝내고 전체 리허설을 1회 완료**할 것

> ⚠️ **`node_modules` 를 통째로 복사하지 마세요.**
> 다른 폴더에서 복사하면 workspace 심볼릭 링크가 **원래 폴더의 절대경로**를 가리켜,
> 코드를 고쳐도 반영되지 않는 문제가 생깁니다. 반드시 새 폴더에서 `npm install` 하세요.
> (v2 개발 중 실제로 겪은 문제입니다 — [검증보고서 E1](04_검증보고서.md))

### Claude Code로 실행하는 방식은?

가능하지만 **시연 실행 수단으로는 권장하지 않습니다.**

- 인터넷이 끊기면 동작하지 않습니다 → 현장 네트워크 장애 시 시연 불가
- 명령 실행·확인에 수십 초가 걸려 관객 앞에서 대기가 생깁니다
- 해외에서 로그인·인증이 막히면 대안이 없습니다

**실행은 `START-DEMO.bat`으로 하고, Claude Code는 문제 발생 시 진단용 백업**으로만 설치해 두세요.

## 8. 공개 터널 (Cloudflare Tunnel) — 네트워크 대비책

### 언제 쓰나

| 상황 | 터널이 해결하는가 |
|---|---|
| 행사장 Wi-Fi가 기기 간 통신 차단(AP 격리) | ✅ |
| **휴대폰이 LTE만 되고 노트북과 다른 망** | ✅ **v2에서 특히 중요** — QR 스캔이 체험의 시작이므로 |
| 인증서 경고가 부담스러움 | ✅ 정식 인증서라 경고 없음 |
| 한국 원격 참관자에게 실시간 시연 | ✅ 주소만 전달 |
| 인터넷 자체가 없음 | ❌ 터널은 인터넷 필수 |

> **v2는 v1보다 터널의 가치가 큽니다.** 고객 휴대폰이 서버에 닿지 못하면 체험을 **시작조차 할 수 없기** 때문입니다.

### 준비 (최초 1회)

```bash
winget install --id Cloudflare.cloudflared -e
```

### 실행

`START-TUNNEL.bat` 더블클릭 → 창 2개가 열립니다.

- **AEPICK - Tunnel Address** 창: 5초쯤 뒤 `https://xxxx.trycloudflare.com` 표시
- **Demo Server** 창: 서버 로그 + **이번 실행용 관리자 키**

터미널 사용 시: `npm run demo:tunnel` (터널은 별도 창에서 `cloudflared tunnel --url http://localhost:8787`)

### 동작 방식

```
휴대폰/태블릿 ──HTTPS(정식 인증서)──▶ Cloudflare ──HTTP──▶ 노트북 :8787
```

- TLS를 Cloudflare가 종단 처리하므로 로컬 서버는 HTTP로 뜹니다
- 서버가 `trustProxy`로 `X-Forwarded-Proto`를 신뢰해 **페어링 QR과 결과 QR이 모두 터널 도메인 + https로 자동 생성**됩니다

### 주의사항

- **주소는 켤 때마다 바뀝니다.** 재시작하면 태블릿에 새 주소를 다시 입력
- **주소를 아는 사람은 누구나 접속 가능합니다.** 시연 시간에만 열고 끝나면 창 2개를 모두 닫습니다
- `TUNNEL=1` 이면 관리자 키가 **매 실행 무작위 생성**됩니다 (서버 창 `ADMIN` 줄에 표시)
- 사내망에서는 **보안 정책을 먼저 확인**합니다. 터널은 "방화벽을 우회해 내부 PC를 외부에 노출하는 행위"로 분류될 수 있습니다
- 무료 `trycloudflare.com` 은 SLA가 없습니다. **주력이 아니라 대비책으로** 둡니다

## 9. 준비물 체크리스트

- [ ] 노트북 (Node 22.13+ 설치, `npm install` 완료)
- [ ] 태블릿 (12인치 이상 권장, 세로 모드, 자동잠금 해제)
- [ ] **휴대폰 2대** (시작 QR용 · 결과 QR용)
- [ ] **휴대용 Wi-Fi 공유기 또는 노트북 핫스팟** ← 현장 Wi-Fi가 불안정할 때 대비
- [ ] (권장) `cloudflared` 설치 — 8번 터널 대비책
- [ ] 노트북 충전기, 태블릿 거치대, 멀티탭
- [ ] 오프라인 대비: 이 문서 인쇄 또는 오프라인 저장

> **가장 흔한 실패 원인은 네트워크입니다.** v2는 QR 스캔으로 체험이 시작되므로
> **휴대폰이 서버에 닿는지**가 v1보다 훨씬 중요합니다.
> 휴대용 공유기를 준비하거나 터널을 켜 두면 현장 Wi-Fi 상태와 무관하게 진행할 수 있습니다.
